WCP Scribe — Browser Test Harness

Open this page in Safari (and Chrome) to confirm the exact same logic the Node tests cover also behaves in the real browser. It runs the shared spec (tests/spec.js) against helpers.js — no build, no mic needed. In Safari it must be served over HTTP (python3 -m http.server), not double-clicked — Safari blocks file:// pages from loading ../helpers.js.

Unit spec

    Recording capability

    What this browser can actually do — and which audio container it will produce. Safari and Chrome disagree here (Safari rejects every WebM type and records MP4/AAC), so this reports what pickAudioMime negotiates against the real MediaRecorder. No microphone permission is requested. 
    Press “Check capabilities”.

    Audio store round-trip

    The crash-safety property, tested for real in this browser: write chunks to IndexedDB exactly as a recording does, read them back, and confirm the reassembled audio is byte-identical and correctly ordered. If this fails in Safari, a recording would not survive a closed tab. Cleans up after itself. 
    Press “Run round-trip”.

    Transcript assembly

    Feeds a realistically-shaped AssemblyAI response — diarized utterances, a split speaker turn, a blank segment — through the real buildUtteranceTranscript the app uses, to prove the speaker-labeled transcript comes out clean. 
    Press “Run simulation”.
